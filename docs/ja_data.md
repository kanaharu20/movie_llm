# 日本の映像で学習データを作る（設計）

2026-10-14。GRPO を 2 回回して「Perception Test で学んだことは Japanese Video-QA に移らない」ことが確定した（`docs/grpo_run2.md`）。題材の差を埋めるため、ベンチマークと同じ種類の映像（日本の行事・観光地・食・文化の YouTube 動画）から、正誤を機械で判定できる問題を作る。

## 方針

| 項目 | 決定 | 理由 |
|---|---|---|
| 映像の入手元 | YouTube の Creative Commons（CC BY）動画 | 再利用が許可されている。yt-dlp の検索フィルタで絞れ、各動画の `license` フィールドで確認できる。NHK クリエイティブ・ライブラリーは規約の確認後に追加を検討 |
| 題材 | ベンチマークの subdomain 100 件（祇園祭、寿司、富士山 …）を検索語にする | 題材をベンチマークに揃える。ベンチマークの 428 本は除外する（評価データの混入を防ぐ） |
| 長さ | 30 秒〜20 分 | ベンチマークの short（<4 分）/ medium（4〜20 分）と同じ範囲。数時間のライブ配信アーカイブを落とす |
| 問題を作るモデル | Qwen3-VL-235B-A22B-Instruct（Apache-2.0、Vercel AI Gateway `alibaba/qwen3-vl-instruct`） | 出力を学習に使うことを規約で禁じていない。GPT / Gemini / Claude は禁じているので使わない。1 回 16 フレームで約 4,400 トークン、27 秒、0.12 円 |
| 問題の形式 | numeric（数）、multi_choice（4 択）、yes_no | 規則採点できる。open は作らない（審判モデル頼みの報酬は報酬ハッキングの入口） |
| 検証 | 同じモデルに別の聞き方で答えさせて一致を見る + 映像なしで答えられる問題を落とす + 学習前の 4B で選別 | 作ったモデルの誤りをそのまま学ばせない。詳細は下 |
| 公開するもの | 問題と答え（動画 ID と時刻つき）、出典一覧（動画 ID・タイトル・チャンネル）、LoRA | フレームや映像は公開しない。CC BY の表示義務は出典一覧で満たす |

## パイプライン

```
1. 候補の検索      scripts/ja_search_cc.py   -> data/ja/candidates.jsonl（id, title, channel, duration, 検索語, domain）
2. 取得            scripts/ja_fetch.py       -> data/ja/videos/<id>.mp4（映像のみ 480p）+ license の確認（CC BY 以外は捨てる）
3. フレーム化      scripts/jvqa_cache_frames.py（既存）-> data/ja/frames/<id>/f32_s640/
4. 問題の生成      scripts/ja_generate.py    -> data/ja/generated.jsonl（1 動画あたり 4〜6 問、根拠の時刻つき）
5. 検証            scripts/ja_verify.py      -> data/ja/verified.jsonl（下の 3 つの検査を通った問題）
6. 選別            scripts/pt_difficulty.py（既存）+ pt_select.py（既存）-> train_ja.jsonl / dev_ja.jsonl
```

### 4. 問題の生成

- 入力: 32 フレーム（各フレームの前に動画内の時刻 `[mm:ss]` を置く）。16 フレームで試したところ、2 分の動画で 4,000 トークン
- 1 本につき、count（数、答えは整数）2 問、temporal（順序・時刻）2 問、action / spatial の 4 択 1〜2 問を作らせる。ベンチマークで弱い count と temporal を多めにする
- 禁止事項を指示に書く: 字幕・テロップの文字を読むだけで答えられる問題、一般常識や有名な場所の知識で答えられる問題、映像の一部の場面にしか当てはまらないのに全体を聞く問題
- 各問に根拠となるフレームの時刻を書かせる（検証と、あとで人が見直すときに使う）
- 出力は JSON。壊れていたら 1 回だけ作り直す

試作（ベンチマークの動画 1 本、16 フレーム）で分かったこと: 形式は守る。ただし「登場人物は何人」で答えが 1 のような易しすぎる問題や、複数の場面で別の動作をしているのに「人物が行っている動作はどれか」と聞く曖昧な問題が出る。易しすぎる問題は 6 の選別で落ち、曖昧な問題は 5 の一致検査で落ちる見込みだが、指示文でも減らす

### 5. 検証（3 つの検査）

1. **再回答の一致**: 問題だけを渡し（答えは渡さない）、同じ 235B に 32 フレームで 2 回答えさせる（温度 0.7）。2 回とも生成時の答えと一致した問題だけ残す。count は「映っているものを 1 つずつ挙げてから数を答える」別の聞き方で答えさせる
2. **映像なしで解けない**: 文章だけのモデル（`alibaba/qwen-3-32b`）に、フレームを渡さず問題だけで 3 回答えさせる。4 択で 3 回とも正解なら「知識や文章の癖で解ける問題」として落とす。count と temporal にも同じ検査をかける
3. **学習前の 4B で選別**: 8 回答えさせて全問正解・全問不正解を落とす（Perception Test と同じ `pt_difficulty.py`）。dev は動画単位で分ける（`pt_select.py`）

残る問題の割合は試作で測る。目安は生成の 50〜60%

## 規模と費用の見積もり

| 段階 | 量 | 時間 | 費用 |
|---|---|---|---|
| 候補の検索 | 106 検索語 × 50 件 | 5 分（手元） | 0 |
| 取得 | 1,000 本 × 約 20MB（480p 映像のみ） | 手元で 1MB/s なら約 6 時間（夜間に回す）。Colab は YouTube に止められることがある | 0 |
| フレーム化 | 1,000 本 × 32 枚 | 手元の CPU で 1〜2 時間 | 0 |
| 生成 | 1,000 本 × 1 回（約 8,000 トークン、32 フレーム） | 8 並列で約 1 時間 | 約 300 円 |
| 検証 1・2 | 5,000 問 × 3 回 | 8 並列で約 5 時間 | 約 1,500 円 |
| 選別 | 3,000 問 × 8 回答（4B、Colab A100） | 約 2 時間 | 約 25 ユニット |

まず **50 本** で 1〜6 を通し、残る問題の割合と質（人が 30 問ほど読む）を見てから 1,000 本に広げる。

## 権利と注意

- CC BY 4.0: 複製・改変・再配布が可能。表示義務は出典一覧（動画 ID・タイトル・チャンネル・URL）で満たす。学習データとして公開する場合は問題文と時刻だけにし、フレームは含めない
- YouTube の利用規約は動画のダウンロードを制限している。本プロジェクトでは研究目的で手元に取得し再配布しない（ベンチマークの動画と同じ扱い）。NHK クリエイティブ・ライブラリーが使えれば、こちらに置き換える
- 日本の著作権法 30 条の 4 により、AI 学習のための複製は原則として許される。CC BY であることで、学習以外の利用（デモでの表示、出典つきの引用）も可能になる
- 動画に写る人物: 公開された動画をそのまま使い、個人を特定する問題（名前、所属）は作らせない。指示文に明記する
- 生成モデルの偏り: 問題は Qwen3-VL-235B の「見え方」に沿う。検査 1 で同じモデルに答えさせるため、モデルが一貫して見誤る問題は残る。dev の一部を人が確認し、誤り率を記録する
