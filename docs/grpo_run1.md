## 読み取り

1. **学習セットには効いたが、ベンチマークには移らなかった。** Perception Test の正解率は上がり、KL も動いているので、学習そのものは機能している。移らなかったのは、題材の差（室内の演技映像、23 秒、3択）と、学習量の少なさ（実質 約 800 問ぶんの更新）の両方が考えられる
2. **count は Perception Test の中でも伸びていない**（dev 27 問で 0、学習中の飛ばし率の増加はほぼ他カテゴリ由来と思われる）。「同じ対象を別のフレームで同一と認識し、重複なく数える」力は、答えの記号だけに報酬を与える今の形では学びにくい可能性がある
3. 日本の映像の読み取り（風景・行事の中の人や物）は Perception Test では学べない、という `docs/perception_test.md` の注意点どおりの結果

## 次に試すこと（優先順）

1. **評価の整備**: dev を学習セットと同じ分布（1〜7/8 の問題）から取り、count と temporal を各 100 問以上にする。これが無いと改善の有無を判定できない
2. **数を答える形式の報酬**: count の 5,499 問は選択肢が全部数字。3択の記号ではなく「数字だけで答える」open 形式にして、正解との差で部分点（|予測 - 正解| = 1 なら 0.5）を与える。記号当てより数える手続きに報酬が結びつく
3. **学習信号の確保**: 飛ばしたグループを別の問題で埋める（DAPO の動的サンプリング）。後半の実質 1.3 問/ステップを 4 問に戻す
4. **データを増やす**: valid 分割（19,140 問、映像 70GB）を加える。Colab の CPU でフレーム化に 10 時間前後
5. **日本の映像を少量足す**: CC BY の YouTube 動画に、Qwen3-VL-32B で数と順序の問題を作って検証したものを混ぜる（`docs/ideas.md` 案 2）

このまま 4B で同じ設定を繰り返しても、ベンチマークの数値は動かないと予想する。1 と 2 を先にやる。
