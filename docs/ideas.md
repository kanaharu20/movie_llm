# スコアを上げるための案（保留メモ）

2026-10-11 時点。友人との議論で出た案と、その時点での検討。実行するときにここから取り出す。状態は「保留」「採用」「却下」のいずれか。

## 1. 学習データを増やす（保留）

- 今は学習データがゼロ。問題は量より入手元
- 候補: NHK クリエイティブ・ライブラリー（規約確認待ち）、YouTube の CC BY 動画（yt-dlp でライセンス絞り込み可、再配布も可）、自前撮影（デモ用）
- 量の目安: SFT 1〜2万件、GRPO 数千件。Video-R1 は SFT 16万 / RL 26万 だが予算に合わない
- 条件: 正誤を機械で判定できる問題であること

## 2. 規約上問題のないモデルで蒸留・データ生成する（保留）

- OpenAI / Google / Anthropic の規約は、出力を使った競合モデルの開発を禁じている。GPT や Gemini に学習用の問題と答えを作らせるとこれに触れる
- 使えるのは Apache-2.0 の Qwen3-VL-32B / 235B など。Llama 系はライセンス表示を守れば可
- 教師の役割は「答えを真似させる蒸留」より「動画から問題と答えを作り、別の方法で検証する」データ作成。例: 同じモデルに2回別の聞き方で答えさせ、一致したものだけ残す
- 純粋な蒸留（教師の回答を SFT で真似させる）は、1段階目の「少量 SFT」に組み込める

## 3. 審判・教師を GPT-4o でなく安いモデル（5 mini など）にする（保留）

- 公式表との比較に使う審判は GPT-4o 固定（1回だけ、数百円）
- 学習中の進捗確認や自分の実験どうしの比較なら安いモデルで可。文章の答え合わせは易しい
- 実測: 4択の採点は規則ベースの方が GPT-4o より正確（一致率 98.3%、不一致 4件はすべて GPT-4o 側の誤り）
- 学習データ生成に使うなら 2 の規約の問題がそのまま当たる

## 4. 学習方法の工夫（保留、優先順位つき）

1. 問題の選別: 学習前のモデルに8回答えさせ、正解率 2〜8割の問題だけ残す。全問正解・全問不正解はグループ内にばらつきがなく GRPO の学習信号が出ない
2. 弱点に寄せる: count（フレーム数で頭打ち）と temporal の比率を上げる
3. 時間順序の報酬（T-GRPO）: フレーム正順とシャッフルで比べ、正順の方が正解できたら加点。temporal がフレーム数で伸びたことと整合
4. 答える前に列挙させる形式: 「映っている人を順に挙げてから数を答える」。2B/4B では長い思考が逆効果になることもあるので小さく試す

## 5. 出力形式に制約をかけて正誤判定しやすくする（方針として採用）

- 評価側は実装済み（記号1文字、はい/いいえ、簡潔に）
- 学習側: 正誤の報酬に加えて小さな形式報酬を置く。形式が崩れると正誤判定もできない
- 推論時の制約付きデコード（Outlines、vLLM の誘導デコード）は製品側で使う。学習時はモデルが自力で形式を守れるよう、報酬で与えて強制はしない
- open 問題は学習に使わない。審判モデル頼みの報酬は報酬ハッキングの入口

## 6. 学習データは海外の映像も使う（保留、有望）

- 2B の失敗は色・物の取り違え、数の過小、順序の誤りが大半で、映像の読み取りそのものの力。題材が日本でなくても鍛えられる
- 軸を分ける: 映像の出どころ（日本/海外）と、問いの言語（日本語）。問いを日本語にすれば言語の面は揃う
- 候補: Perception Test（数・時間順序、注釈 Apache-2.0、映像 CC BY）、CLEVRER（合成、数・因果）。NExT-QA は非営利ライセンスなので Apache で LoRA を出すなら避ける
- 英語の問いと答えは Qwen3 の文章モデルで日本語に訳す（規約の問題なし、無料）。選択式と数を答える問題だけ訳せば正誤判定もそのまま
- 注意: 対外資料は「日本の映像に特化」。特化の対象を「日本語の問いと日本の映像での評価」に置き直す。日本固有の要素（着物、神社、行事）は海外の映像では学べないので、日本の映像（CC BY の YouTube、自前撮影）を少量足す
- 実験の切り口: 「海外の映像だけ」と「日本の映像を足す」を比べ、日本の映像の効果を数値で示す

## 計算資源: Google Colab（学生プラン）の使い分け（方針として採用）

| 作業 | GPU 時間の目安 | Colab での現実性 |
|---|---|---|
| 4B のベースライン評価（32フレーム、800問） | A100 で 2〜3時間 | 向いている |
| 2B で数千件の GRPO 試行（コスト計測） | A100 で 5〜15時間 | 月の枠内で 1回 |
| 4B の GRPO 本番（1回 50〜120時間） | 600〜1,400 ユニット | 枠を超える。INDX の GPU を使う |

- Colab は「INDX の GPU を使う前の準備場所」。4B 評価、学習スクリプトのデバッグ、2B の小さな GRPO 試行まで
- 落とし穴: セッション最長 24時間で途中切断あり（Drive へこまめにチェックポイント）、Colab の IP からは YouTube 取得が弾かれやすい（手元の 390本・7GB を Drive に上げる）、バックグラウンド実行は Pro+ のみ
- 4B の GRPO は 32フレーム × 8回答で A100 40GB でも厳しい。フレーム 16 か回答 4本に落とす
- 検索で確認できた公式の学生向け無料提供は米国の高等教育機関限定（2026年時点）。日本の学生向け価格は料金ページで確認する
